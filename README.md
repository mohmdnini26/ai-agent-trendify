# 🤖 ایجنت هوش مصنوعی تلگرام (Cloudflare Workers + D1)

یک ایجنت شخصی که روی **Cloudflare Workers** اجرا می‌شود، ۲۴ ساعته روشن است و هزینه‌ی سرور ندارد. از طریق تلگرام باهاش حرف می‌زنی و او:

- 🧠 **یاد می‌گیرد:** چیزهای مهم را در حافظه‌ی بلندمدت ذخیره می‌کند
- 🛠 **اسکیل می‌سازد:** وقتی بگویی «از این به بعد ...»، یک دستورالعمل رفتاری می‌سازد و در گفتگوهای بعدی رعایت می‌کند
- 🔎 **در وب جستجو می‌کند** و محتوای لینک‌ها را می‌خواند
- 🔌 **به سرویس‌ها وصل می‌شود** (گیت‌هاب، کلودفلر و هر سرویسی که API و توکن دارد) و برایت کار انجام می‌دهد
- 🚀 **Worker و سایت منتشر می‌کند** روی حساب کلودفلر تو
- 🔐 **برای هر کار خطرناک تأیید می‌گیرد** (دکمه ✅ / ❌)
- 💾 **بکاپ خودکار** در یک ریپوی خصوصی گیت‌هاب
- 📊 **گزارش هفتگی** از چیزهایی که یاد گرفته

## نحوه‌ی کار

```
تلگرام ──webhook──▶ Cloudflare Worker ──▶ مدل هوش مصنوعی (TokenHarbor / Groq / ...)
                         │
                         ├──▶ D1  (حافظه، اسکیل‌ها، تاریخچه، توکن‌های رمزنگاری‌شده، لاگ کارها)
                         ├──▶ ابزارها (جستجوی وب، خواندن صفحه، API سرویس‌ها، دیپلوی Worker)
                         └──▶ GitHub (بکاپ شبانه)
```

**حلقه‌ی یادگیری:** مدل در همان یک تماس، هم جواب می‌دهد و هم می‌گوید چه چیزی باید ذخیره شود. ربات آن بخش را جدا می‌کند و در D1 می‌نویسد. هر شب حافظه مرتب و فشرده می‌شود و هر جمعه گزارش هفتگی می‌آید.

## نصب مرحله‌به‌مرحله

> همه‌ی مراحل از داشبورد کلودفلر انجام می‌شود و نیازی به نصب برنامه نیست.

### ۱) ساخت ربات تلگرام

1. در تلگرام `@BotFather` را باز کن و بنویس `/newbot`
2. یک اسم و یک یوزرنیم (که به `bot` ختم شود) بده
3. توکنی که می‌دهد (شبیه `123456789:AAH...`) را کپی کن؛ این **`TELEGRAM_TOKEN`** است

### ۲) گرفتن کلید مدل زبانی

از سایت سرویس مدل (TokenHarbor یا Groq) ثبت‌نام کن و یک API Key بساز. این **`AI_API_KEY`** است.

> اگر TokenHarbor استفاده می‌کنی: مدل‌های رایگان را باید در داشبورد خودش فعال کنی و سهمیه‌ی رایگان روی یک بازه‌ی ۷ روزه‌ی غلتان حساب می‌شود.

### ۳) ساخت دیتابیس D1

1. داشبورد کلودفلر ← **Storage & databases** ← **D1 SQL Database** ← **Create Database**
2. اسمش را بگذار `agent-db`

**لازم نیست جدولی بسازی.** ربات جدول‌ها را در اولین اجرا خودش می‌سازد.

### ۴) ساخت Worker و گذاشتن کد

1. **Compute (Workers)** ← **Workers & Pages** ← **Create** ← **Start with Hello World**
2. یک اسم بده (مثلاً `ai-agent`) و **Deploy** بزن
3. **Edit code** ← کل کد پیش‌فرض را پاک کن ← محتوای فایل `ai.js` را جایگزین کن ← **Deploy**
4. آدرس ورکر را کپی کن (مثلاً `https://ai-agent.yourname.workers.dev`). این **`WORKER_URL`** است

### ۵) وصل کردن دیتابیس به Worker

**Settings** ← **Bindings** ← **Add** ← **D1 database**

- Variable name: دقیقاً `DB` (حروف بزرگ)
- Database: `agent-db`

### ۶) تعریف متغیرها

از **Settings** ← **Variables and secrets** همه‌ی متغیرهای [جدول زیر](#جدول-کامل-متغیرها) را اضافه کن، سپس **Deploy** بزن.

> ⚠️ بعد از هر تغییر در متغیرها حتماً Deploy بزن، وگرنه اثر نمی‌کند.

### ۷) وصل کردن تلگرام به Worker (وب‌هوک)

این لینک را با مقدارهای خودت بساز و در **مرورگر** باز کن:

```
https://api.telegram.org/botTELEGRAM_TOKEN/setWebhook?url=WORKER_URL&secret_token=WEBHOOK_SECRET
```

دقت کن: بین `bot` و توکن فاصله یا `/` نباشد. پاسخ درست:

```json
{"ok":true,"result":true,"description":"Webhook was set"}
```

برای بررسی وضعیت: `https://api.telegram.org/botTELEGRAM_TOKEN/getWebhookInfo`

### ۸) پیدا کردن `OWNER_ID`

1. به ربات پیام بده (مثلاً «سلام»)
2. جواب می‌دهد: «OWNER_ID تنظیم نشده. آیدی چت شما: 123456789»
3. آن عدد را به‌عنوان متغیر `OWNER_ID` (نوع Text) اضافه کن و Deploy بزن

از این به بعد **فقط تو** می‌توانی با ربات حرف بزنی.

### ۹) فعال کردن Cron (پاکسازی شبانه، بکاپ، گزارش هفتگی)

Worker ← **Settings** ← **Trigger Events** ← **Cron Triggers** ← **Add** ← مقدار:

```
0 2 * * *
```

(هر شب ساعت ۲ UTC. گزارش هفتگی هر جمعه همین ساعت ارسال می‌شود.)

### ۱۰) تست

```
/start
اسمم علی است و عاشق فوتبالم
/memories
```

بعد از پیام دوم باید زیر جواب ربات بنویسد «🧠 حافظه: ...» و `/memories` همان را نشان دهد.

## جدول کامل متغیرها

در **Settings ← Variables and secrets** اضافه کن. نوع **Secret** یعنی بعد از ذخیره دیگر دیده نمی‌شود.

### اجباری

| نام | نوع | مقدار | توضیح |
|---|---|---|---|
| `TELEGRAM_TOKEN` | Secret | توکن BotFather | شناسه‌ی ربات |
| `AI_API_KEY` | Secret | کلید سرویس مدل | |
| `WEBHOOK_SECRET` | Secret | یک رشته‌ی تصادفی (فقط `A-Z a-z 0-9 _ -`) | جلوگیری از درخواست‌های جعلی به ورکر. باید با `secret_token` در لینک وب‌هوک **یکی** باشد |
| `AI_API_URL` | Text | `https://tokenharbor.ai/v1/chat/completions` | آدرس کامل endpoint چت |
| `AI_MODEL` | Text | `deepseek-v4.1-flash:free` | نام مدل |
| `OWNER_ID` | Text | آیدی عددی چت تو | فقط این شخص اجازه‌ی استفاده دارد |
| `DB` | **Binding** (D1) | `agent-db` | از بخش Bindings، نه Variables |

### برای اتصال به سرویس‌ها و دیپلوی (توصیه‌شده)

| نام | نوع | مقدار | توضیح |
|---|---|---|---|
| `VAULT_KEY` | Secret | رشته‌ی تصادفی ≥ ۳۲ حرف | توکن سرویس‌ها با آن رمزنگاری (AES-GCM) می‌شود. **بدون آن `/connect` کار نمی‌کند.** اگر بعداً عوضش کنی، باید سرویس‌ها را دوباره `/connect` کنی |
| `SELF_WORKER_NAME` | Text | اسم همین ورکر (مثلاً `ai-agent`) | ربات هیچ‌وقت نمی‌تواند خودش را با `deploy_worker` بازنویسی کند |

ساخت یک `VAULT_KEY` تصادفی (روی لینوکس/مک):
```bash
head -c 64 /dev/urandom | base64 | tr -dc 'A-Za-z0-9' | head -c 40
```

### اختیاری

| نام | نوع | مقدار | توضیح |
|---|---|---|---|
| `TIMEZONE` | Text | مثلاً `Europe/Berlin` یا `Asia/Tehran` | تاریخ و ساعت درست (میلادی و شمسی) برای ربات. پیش‌فرض: UTC |
| `TAVILY_API_KEY` | Secret | کلید Tavily | جستجوی وب با سهمیه‌ی بیشتر. بدون آن هم جستجو کار می‌کند ولی محدودتر |
| `AI_VISION` | Text | `1` | فعال‌کردن خواندن عکس و اسکرین‌شات. فقط وقتی بگذار که مدل اصلی تصویر می‌فهمد (مثل `gemini-3.5-flash`). مدل‌های متنی خطا می‌دهند |
| `AI_REASONING_EFFORT` | Text | `low` | فقط برای مدل‌هایی که «فکر کردن» دارند (مثل Gemini 3.x): سرعت را بالا می‌برد. اگر سرویس شما نمی‌شناسد، اضافه نکن |
| `AI_FALLBACK_URL` | Text | آدرس endpoint یک سرویس دوم | اگر سرویس اصلی خطا داد (مثلاً سهمیه تمام شد)، خودکار سراغ این می‌رود |
| `AI_FALLBACK_MODEL` | Text | نام مدل سرویس دوم | |
| `AI_FALLBACK_KEY` | Secret | کلید سرویس دوم | |
| `GITHUB_TOKEN` | Secret | توکن Fine-grained گیت‌هاب | برای بکاپ خودکار (دسترسی Contents: Read and write فقط روی ریپوی بکاپ) |
| `GITHUB_REPO` | Text | `username/agent-backup` | ریپوی **خصوصی** بکاپ (باید حداقل یک فایل مثل README داشته باشد) |

### نمونه‌ی سرویس‌های مدل

| سرویس | `AI_API_URL` | `AI_MODEL` |
|---|---|---|
| TokenHarbor (رایگان) | `https://tokenharbor.ai/v1/chat/completions` | `deepseek-v4.1-flash:free` |
| Google Gemini (AI Studio) | `https://generativelanguage.googleapis.com/v1beta/openai/chat/completions` | `gemini-3.5-flash` |
| Groq | `https://api.groq.com/openai/v1/chat/completions` | `llama-3.3-70b-versatile` (یا هر مدلی که در کنسول Groq هست) |

### معادل `wrangler.toml` (اگر با CLI کار می‌کنی)

```toml
name = "ai-agent"
main = "ai.js"
compatibility_date = "2025-01-01"

[vars]
AI_API_URL = "https://tokenharbor.ai/v1/chat/completions"
AI_MODEL = "deepseek-v4.1-flash:free"
OWNER_ID = "123456789"
TIMEZONE = "Europe/Berlin"
SELF_WORKER_NAME = "ai-agent"
GITHUB_REPO = "username/agent-backup"

[[d1_databases]]
binding = "DB"
database_name = "agent-db"
database_id = "ID_FROM_CLOUDFLARE"

[triggers]
crons = ["0 2 * * *"]
```

سکرت‌ها را با CLI این‌طور بده:

```bash
npx wrangler secret put TELEGRAM_TOKEN
npx wrangler secret put AI_API_KEY
npx wrangler secret put WEBHOOK_SECRET
npx wrangler secret put VAULT_KEY
npx wrangler secret put GITHUB_TOKEN      # اختیاری
npx wrangler secret put TAVILY_API_KEY    # اختیاری
```

## دادن توکن سرویس‌ها به ربات

ربات خودش نمی‌تواند برای سرویسی توکن بسازد. تو یک بار توکن می‌سازی (با **کمترین دسترسی لازم**) و با `/connect` می‌دهی.

### فرمت دستور

```
/connect نام آدرس_پایه توکن [نام_هدر] [پیشوند]
```

| بخش | توضیح |
|---|---|
| `نام` | یک اسم انگلیسی دلخواه (۲ تا ۳۰ حرف/عدد/`-`/`_`). ربات با همین اسم سرویس را صدا می‌زند |
| `آدرس_پایه` | آدرس API سرویس، **حتماً https** |
| `توکن` | همان توکن/کلید سرویس |
| `نام_هدر` | اختیاری. پیش‌فرض `Authorization` |
| `پیشوند` | اختیاری. پیش‌فرض برای `Authorization` برابر `Bearer` و برای هدرهای دیگر خالی است. برای «بدون پیشوند» بنویس `-` |

بعد از ذخیره، ربات **پیام حاوی توکن را از چت پاک می‌کند**.

### مثال‌ها

**گیت‌هاب**

1. GitHub ← Settings ← Developer settings ← Personal access tokens ← **Fine-grained tokens** ← Generate
2. فقط ریپوهای لازم را انتخاب کن و فقط دسترسی‌های لازم را بده (مثلاً Issues و Contents)

```
/connect github https://api.github.com ghp_توکن_تو
```

**کلودفلر**

1. داشبورد ← My Profile ← API Tokens ← Create Token ← قالب **Edit Cloudflare Workers** (یا توکن سفارشی با Workers Scripts: Edit و Account Settings: Read)
2. Account Resources را روی حساب خودت بگذار

```
/connect cloudflare https://api.cloudflare.com/client/v4 توکن_کلودفلر
```

**سرویسی که کلید را در هدر دلخواه می‌خواهد (مثلاً `X-Api-Key`)**

```
/connect mysite https://api.mysite.com کلید_تو X-Api-Key
```

**سرویسی که پیشوند خاص می‌خواهد (مثلاً `token xxx`)**

```
/connect svc https://api.svc.com کلید_تو Authorization token
```

> سرویس‌های معمول با Bearer Token (مثل Vercel یا Netlify) هم با همین الگو کار می‌کنند؛ آدرس پایه‌ی دقیق را از مستندات خودشان بردار.
> **سرویس‌هایی که علاوه بر توکن، هدر اجباری دیگری لازم دارند (مثل `Notion-Version` در Notion) فعلاً پشتیبانی نمی‌شوند.**

### مدیریت

| کامند | کار |
|---|---|
| `/services` | لیست سرویس‌های متصل (بدون توکن) |
| `/disconnect نام` | حذف سرویس و توکن |
| `/audit` | ۱۰ کار آخری که روی سرویس‌ها انجام شده |

> بعد از `/disconnect`، توکن را در خود سرویس هم **revoke** کن.

### چطور استفاده کنم؟

فقط عادی بنویس:

- «ریپوهای من در گیت‌هاب را لیست کن»
- «در ریپوی my-app یک ایشو با عنوان "باگ لاگین" باز کن»
- «آخرین کامیت‌های ریپوی my-app را خلاصه کن»

خواندن (GET) مستقیم انجام می‌شود. **هر نوشتن یا حذف** (POST/PUT/PATCH/DELETE) اول درخواست دقیق را نشانت می‌دهد و با دکمه تأیید می‌گیرد.

## ساخت سایت با Worker

بعد از اتصال کلودفلر (بالا)، بگو:

> با کلودفلر یک سایت تک‌صفحه‌ای فارسی برای معرفی من بساز و منتشر کن

ربات:
1. شناسه‌ی حساب را پیدا می‌کند
2. **کد کامل Worker را در چت نشان می‌دهد**
3. دکمه‌ی 🚀 **منتشر کن** / ❌ می‌دهد (اگر Worker با همان نام از قبل باشد، هشدار «جایگزین می‌شود» می‌آید)
4. بعد از تأیید، آپلود می‌کند، آدرس workers.dev را فعال می‌کند و لینک `نام.زیردامنه.workers.dev` را می‌دهد

می‌توانی بعدش بگویی «رنگ‌ها را تیره کن» تا دوباره منتشر کند.

> اگر حسابت زیردامنه‌ی workers.dev ندارد، یک بار در داشبورد (Workers & Pages) بساز.

| `/debug` | آخرین خروجی خام بخش یادگیری (برای عیب‌یابی) |

## امنیت

- **فقط مالک:** هر پیام یا دکمه از غیر `OWNER_ID` نادیده گرفته می‌شود
- **وب‌هوک محافظت‌شده** با `WEBHOOK_SECRET`
- **توکن‌ها رمزنگاری می‌شوند** (AES-GCM با `VAULT_KEY`) و **مدل هرگز توکن را نمی‌بیند**؛ فقط کد موقع تماس آن را تزریق می‌کند
- **بکاپ گیت‌هاب شامل هیچ توکنی نیست** (فقط حافظه، اسکیل‌ها و شخصیت)
- **تأیید با دکمه** برای هر نوشتن، حذف و دیپلوی
- آدرس نهایی هر درخواست **همیشه روی دامنه‌ی همان سرویس** می‌ماند و ریدایرکت‌ها دنبال نمی‌شوند
- اگر سرویس توکن را در پاسخش برگرداند، `[REDACTED]` می‌شود
- **ضد تزریق دستور:** یادگیری خودکار بعد از استفاده از ابزار (وب یا سرویس) غیرفعال است و فقط **به‌صورت پیشنهاد با دکمه** می‌آید، تا یک صفحه یا ایمیل مخرب نتواند به ربات دستور مخفی بدهد
- هر درخواست به سرویس‌ها در `/audit` ثبت می‌شود
- پیام‌های تکراری تلگرام نادیده گرفته می‌شوند

### توصیه‌ها

- توکن‌ها را **Fine-grained و کم‌دسترسی** بساز
- توکن کلودفلر نمی‌تواند به یک Worker خاص محدود شود؛ آن را فقط برای همین کار بساز و در صورت نیاز حذف کن
- هر توکنی که جایی لو رفت (چت، اسکرین‌شات، ویدیو) را فوراً **revoke** کن (برای ربات تلگرام: `@BotFather` ← `/revoke`)
- توکن‌ها از سرورهای تلگرام عبور می‌کنند (رمزنگاری سرتاسری ندارد). پیامش پاک می‌شود، ولی دسترسی توکن را حداقلی نگه دار

## حریم خصوصی

هر چیزی که ربات می‌خواند (پیام‌ها، حافظه‌ها، اسکیل‌ها، و داده‌هایی که از سرویس‌ها می‌گیرد مثل ایمیل یا ریپوی خصوصی) **برای مدل زبانی فرستاده می‌شود**.

- طبق سیاست TokenHarbor، در **مسیر رایگان** گفتگوها ممکن است نگه‌داری شوند، کارکنان بتوانند ببینند و ارائه‌دهنده‌ی مدل طبق شرایط خودش استفاده کند. در مسیر پولی طبق گفته‌ی سایت این‌طور نیست.
- پس **اطلاعات حساس** (رمز، اطلاعات مالی، مدارک) را به ربات نده و سرویس‌های حاوی داده‌ی خصوصی را فقط با مسیر پولی یا مدلی که به آن اعتماد داری وصل کن.
- پرس‌وجوهای جستجوی وب به Tavily فرستاده می‌شود.

## رفع مشکل

برای دیدن خطاهای دقیق: Worker ← **Observability** ← **Logs**

| مشکل | علت احتمالی | راه‌حل |
|---|---|---|
| وب‌هوک `404 Not Found` می‌دهد | بین `bot` و توکن در لینک فاصله یا `/` هست | لینک را بدون فاصله بساز: `.../botTOKEN/setWebhook...` |
| ربات جواب نمی‌دهد | وب‌هوک ست نشده، `WEBHOOK_SECRET` یکی نیست یا `OWNER_ID` اشتباه است | `getWebhookInfo` را ببین و مقدارها را چک کن |
| بعد از تغییر متغیر اثری نیست | Deploy نزده‌ای | Deploy بزن |
| «OWNER_ID تنظیم نشده» | متغیر هنوز اضافه نشده | مرحله‌ی ۸ |
| `⚠️ AI_ERROR HTTP 401/403` | کلید یا دسترسی مدل اشتباه است | `AI_API_KEY` را چک کن |
| `⚠️ AI_ERROR HTTP 429` | سقف درخواست یا سهمیه‌ی رایگان تمام شده | نوار سهمیه‌ی داشبورد را ببین یا مدل/سرویس را عوض کن |
| `⚠️ AI_ERROR ... (پاسخ خالی)` | مدل جواب خالی داد (یا مدل رایگان فعال نشده) | مدل رایگان را در داشبورد فعال کن یا مدل دیگر بگذار |
| چیزی ذخیره نمی‌شود | مدل بخش یادگیری را ننوشته یا JSON خراب داده | `/debug` را ببین؛ مدل قوی‌تر بگذار؛ یا از `/learn` استفاده کن |
| `/connect` می‌گوید VAULT_KEY لازم است | Secret ساخته نشده | جدول متغیرها |
| «رمزگشایی توکن ناموفق بود» | `VAULT_KEY` عوض شده | سرویس را دوباره `/connect` کن |
| `/backup` خطا می‌دهد | توکن گیت‌هاب دسترسی Contents ندارد یا ریپو خالی است | یک README به ریپو اضافه کن و دسترسی را چک کن |
| دیپلوی: «زیردامنه پیدا نشد» | حساب workers.dev ندارد | در داشبورد یک زیردامنه بساز |
| دیپلوی: HTTP 403 | توکن کلودفلر دسترسی Workers Scripts: Edit ندارد | توکن را دوباره بساز |
| سایت منتشر شد ولی باز نمی‌شود | چند ثانیه طول می‌کشد | کمی بعد دوباره امتحان کن |
| ربات وسط کار ساکت شد | محدودیت CPU/زمان ورکر (مخصوصاً پلن رایگان) | بنویس «ادامه بده». ربات کار قبلی را یادش است و می‌گوید نوبت قبلی قطع شده بود. لاگ‌ها را هم ببین |
| جواب‌ها کند است | مدل رایگان کند است یا کار چندمرحله‌ای است | مدل سبک‌تر یا Groq |

## محدودیت‌ها

- ورودی: **متن** و (با `AI_VISION=1` و یک مدل بینا مثل Gemini) **تصویر/اسکرین‌شات**. صدا و فایل‌های دیگر پشتیبانی نمی‌شوند
- «یادگیری» از طریق حافظه و اسکیل‌های متنی است؛ وزن‌های مدل تغییر نمی‌کند
- سرویس‌هایی که هدر اجباری اضافه (غیر از توکن) می‌خواهند فعلاً پشتیبانی نمی‌شوند
- سرویس‌هایی که فقط با OAuth کار می‌کنند (مثل Gmail و Google Calendar) هنوز پشتیبانی نمی‌شوند
- سایت منتشرشده فعلاً **یک Worker تک‌فایل** است که HTML را خودش برمی‌گرداند (نه سایت چندفایلی با عکس)
- خروجی هر پاسخ به حدود ۳۵۰۰ توکن محدود است
- هر پیام حداکثر ۶ مرحله استفاده‌ی پشت‌سرهم از ابزار دارد و حدود ۴۰ ثانیه فرصت
- مدل‌های رایگان گاهی قالب خروجی را رعایت نمی‌کنند؛ در این صورت جواب سالم می‌رسد ولی آن بار چیزی ذخیره نمی‌شود
- فقط آخرین ۳۰۰ پیام نگهداری می‌شود
